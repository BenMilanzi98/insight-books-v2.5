# Phase 1–3 Evidence Index — Inputs to the Phase 4 Posting Engine

Phase 4 of the InsightBooks V2 accounting reconstruction. This index records every
previous-phase finding or decision that constrains the Central Accounting Posting
Engine, with its source evidence and the control Phase 4 must implement.

Evidence locations in this repository:

| Phase | Evidence root |
|---|---|
| Phase 1 — Forensic audit | `docs/accounting-audit/` |
| Phase 2 — Target architecture & transition foundation | `docs/accounting-architecture/` |

No findings below are invented; each row cites the phase document (and, where
useful, the code) in which it was established.

## 4. Cross-phase dependency notes

- **Account mapping dependency**: every non-manual template depends on P3-01/P3-02.
  Manual journals take explicit account IDs and depend only on P3-03 account validation.
- **Period dependency**: the engine uses the current period implementation
  (`lib/accountingPeriodService.js`) behind `engine/periodResolution.js`; the silent-skip
  behaviour (P1-08) is *not* reproduced — an unlocatable period becomes an explicit error
  when strict period resolution is enabled for the event. Phase 8 replaces the resolver.
- **Approval dependency**: no dedicated approval framework exists in the legacy codebase
  beyond role checks. Phase 4 implements approval requirement resolution + separation of
  duties inside the engine (see `APPROVAL_INTEGRATION.md`); manual journal approvals are
  recorded on the V2 journal row and the event registry.
- **Legacy compatibility dependency**: `postGlEntry` and `journalService.postEntry`
  remain authoritative for LEGACY-mode events; Phase 4 adds the legacy posting guard so
  they refuse events for which NEW_ENGINE is active (P2-06, P1-01).
- **Migration risk**: all Phase 4 schema changes are additive; historical journals,
  transactions and balances are never modified. Legacy duplicate repair remains with
  Phase 6.
