Security posture

Identity and access

Authentication middleware, HTTP-only admin cookies, JWT-backed sessions, and role-based permissions limit access by responsibility.

  • Tenant roles with JSON permission sets
  • Admin APIs protected by admin session checks
  • Branch access support for multi-location businesses

Application safeguards

The application uses Prisma ORM, input validation patterns, and structured API boundaries to reduce common web and data risks.

  • SQL injection protection through parameterized ORM access
  • Server-side route checks for protected workflows
  • Financial operations constrained by business rules

Hardened deployment

Production Docker configuration reduces runtime exposure and keeps the app environment consistent across releases.

  • Multi-stage image build
  • Non-root application user
  • No-new-privileges and read-only app filesystem

Financial integrity

For accounting software, integrity is security.

InsightBooks treats posted financial records as business evidence. Material changes are handled through reversal, reason capture, and audit logs instead of silent deletion.

No silent removal

Posted money movement is reversed with equal-and-opposite entries where applicable.

Reason required

User-initiated removals require a meaningful reversal reason for review and accountability.

Audit evidence

Structured audit log entries preserve who did what, when, and why.

Protected totals

Invoices, payments, sales, supplier bills, and purchase flows update balances through controlled workflows.

Data privacy

Privacy is designed around minimum necessary access.

01Tenant separation
Business data is scoped by tenant so one company does not browse another company's records.
02Role limits
Finance, stock, HR, reporting, and admin actions can be exposed only to assigned roles.
03Branch controls
Users can be restricted to the branches and operating locations they are allowed to manage.
04Audit visibility
Administrative and financial events can be reviewed when privacy questions arise.

Privacy is not only about hiding data. It is about making sure each user sees enough to do their job, and no more.

System uptime

Availability is engineered at the runtime, database, and recovery layers.

Detect

Container health checks verify the app and PostgreSQL are reachable.

Restart

Production services use restart policies to recover from transient failure.

Restore

Documented backup and restore workflows support recovery after database issues.

Validate

Deployment guides, runbooks, and validation scripts reduce release risk.

Operational commitments to present

  • Target uptime: 99.5%+ for hosted production environments, excluding scheduled maintenance.
  • Maintenance windows: communicated in advance for planned releases or database work.
  • Recovery objective: restore from the latest verified backup as the primary recovery path.
  • Escalation: production incidents prioritized ahead of standard support requests.

Backup and continuity

Database first

InsightBooks relies on PostgreSQL as the system of record, with documented dump, restore, and migration procedures.

Release safety

Deployment guides recommend controlled builds, environment configuration, and checks before production updates.

Business continuity

POS service worker support improves the user experience during intermittent connectivity for selected workflows.

Restore readiness

Restore scripts and runbooks give support teams a repeatable path instead of improvising during an outage.

Data protection

Backups should be encrypted, access-limited, and tested on a schedule as part of the operating policy.

Improvement roadmap

Add automated off-site backup verification, incident dashboards, and formal RPO/RTO reporting for enterprise clients.
