# 2. 🎯 Core Objective

Allow users to:

* Plan **Revenue (Forecast)**
* Plan **Expenses (Budget)**
* Compare against **Actuals (from accounting)**
* Track **performance (variance + progress)**

👉 End result:
**A live P&L with targets vs actuals**

---

# 3. 🧱 Core Architecture

You are extending:

* Chart of Accounts
* Transactions (Invoices, Expenses)
* Reporting Engine

---

## 🗄️ New Tables

---

### 1. Budget_Header

```sql
budget_headers
- id
- name (e.g. 2026 Annual Budget)
- period_type (monthly, quarterly, yearly)
- start_date
- end_date
- created_by
- status (draft, active)
```

---

### 2. Budget_Lines

```sql
budget_lines
- id
- budget_id
- account_id (linked to chart of accounts)
- period (e.g. Jan, Q1, 2026-01)
- planned_amount
```

---

### 3. Forecast_Header

```sql
forecast_headers
- id
- name
- period_type
- start_date
- end_date
- version (v1, v2 revisions)
- status
```

---

### 4. Forecast_Lines

```sql
forecast_lines
- id
- forecast_id
- account_id (mainly revenue accounts)
- period
- planned_amount
```

# 4. 🧠 Core Logic

---

## A. Actuals Source

Actual data comes from:

* Revenue → Invoices
* Expenses → Expense transactions

---

## B. Variance Formula

👉 This is the heart of the system:

\text{Variance} = \text{Actual} - \text{Planned}

---

## C. Performance %

\text{Performance %} = \frac{\text{Actual}}{\text{Planned}} \times 100

---

# 9. ⚙️ BACKEND LOGIC

---

## A. Get Actual Revenue

```sql
SELECT SUM(amount)
FROM invoices
WHERE account_type = 'revenue'
AND date BETWEEN start_date AND end_date
```

---

## B. Get Actual Expenses

```sql
SELECT SUM(amount)
FROM expenses
WHERE date BETWEEN start_date AND end_date
```

---

## C. Match Periods

System must map:

* Transactions → correct period (month/quarter)
