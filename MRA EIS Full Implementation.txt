2. FEATURE-AVAILABILITY MODEL
======================================================================

MRA EIS must be optional.

Implement two separate levels of control.

LEVEL 1 — SYSTEM ADMINISTRATOR ENTITLEMENT

The InsightBooks System Administrator controls whether the EIS capability is available to a tenant.

Suggested field:

systemAdminEisEntitlementEnabled

Default:

false

When false:

- The tenant cannot activate EIS.
- EIS setup pages are unavailable to tenant users.
- EIS sales transmission does not run.
- EIS credentials cannot be entered.
- Existing historical EIS transmission records remain readable to authorized support personnel.
- No queued record may be deleted.

Only an authorized System Administrator may change this entitlement.

LEVEL 2 — TENANT OPERATIONAL SETTING

After System Administration enables the entitlement, an authorized Tenant or Business Administrator may choose whether to configure and operate EIS.

Suggested field:

tenantEisOperationalEnabled

Default:

false

The tenant must complete:

- MRA registration
- Terminal acquisition
- Terminal activation
- Product or service synchronization
- Branch or site mapping
- Tax mapping
- Receipt configuration
- Connectivity validation

before the status can become ACTIVE.

The two-level rule must be:

Effective EIS Enabled =
System Admin Entitlement
AND
Tenant Operational Setting
AND
Valid Activated Terminal
AND
Valid Current Configuration
AND
Terminal Not Blocked

Do not merge system entitlement and tenant activation into one Boolean field.

======================================================================
31. UNCERTAIN OUTCOME AND TIMEOUT SAFETY
======================================================================

A network timeout does not prove that MRA rejected the transaction.

When a request times out after transmission:

- Mark the result UNKNOWN_OUTCOME.
- Do not immediately generate a new fiscal invoice number.
- Do not blindly resubmit.
- Query Last Submitted Online Transaction.
- Compare MRA’s returned invoice number and payload details.
- Reconcile the response with the local snapshot.
- If found, mark the original accepted.
- If not found after the approved reconciliation process, retry using the same fiscal identity where permitted.
- Record every attempt.

This control is mandatory for preventing duplicate MRA invoices.

======================================================================
33. CONFIGURATION-REFRESH RESPONSE
======================================================================

When MRA returns `shouldDownloadLatestConfig = true`:

- Pause subsequent EIS submissions for that terminal.
- Call Get Latest Configuration.
- Validate the response.
- Save a new versioned snapshot.
- Revalidate tax and levy mappings.
- Activate the configuration.
- Resume transmission.
- Record the update.
- Alert administrators if mapping conflicts arise.

Do not continue submitting indefinitely with a configuration MRA has marked stale.

======================================================================
34. TERMINAL BLOCKING
======================================================================

When MRA returns `shouldBlockTerminal = true`:

- Mark terminal BLOCKED_BY_MRA.
- Stop EIS-dependent sales processing for that terminal.
- Call Get Terminal Blocking Message.
- Store the block reason.
- Display a clear message to the cashier and administrator.
- Create a critical Audit Event.
- Send appropriate notifications.
- Prevent bypass by frontend manipulation.
- Do not use another tenant’s terminal.
- Do not silently route sales through an unrelated terminal.

Use Check Terminal Unblock Status according to the verified contract.

After unblock:

- Refresh configuration.
- Verify terminal status.
- Resume only after all checks pass.

- Terminal is not blocked.
- Local secure queue is available.

36. OFFLINE TRANSACTION FLOW

65. END-TO-END WORKFLOWS
======================================================================

WORKFLOW 1 — SYSTEM ENTITLEMENT:

System Administrator
→ Select tenant
→ Enable EIS entitlement
→ Tenant sees EIS as available
→ Tenant cannot use it until configured
→ Audit Event is created

WORKFLOW 2 — TERMINAL ACTIVATION:

Tenant Administrator
→ Open EIS setup
→ Complete readiness checklist
→ Enter TAC
→ Submit activation
→ Persist encrypted credentials
→ Persist configuration
→ Confirm activation
→ Terminal becomes ACTIVE
→ TAC is no longer reusable

WORKFLOW 3 — PRODUCT SYNCHRONIZATION:

Active terminal
→ Fetch site products and services
→ Match local Items
→ Resolve unmapped Items
→ Map MRA tax rates
→ Validate all products
→ Mark Business ready for Sales

WORKFLOW 4 — ONLINE POS SALE:

Create POS Sale
→ Post local Accounting Journal
→ Create immutable EIS snapshot
→ Generate fiscal number
→ Submit to MRA
→ Receive validation URL
→ Generate QR
→ Print receipt
→ EIS status becomes ACCEPTED_ONLINE
→ Accounting remains posted once

WORKFLOW 5 — SALES INVOICE:

Create Sales Invoice
→ Approve and issue
→ Post Revenue, Tax and Receivable
→ Send one EIS Sale transaction
→ Receive QR
→ Display both local Invoice number and MRA fiscal number
→ Later Customer payment does not resubmit Revenue

WORKFLOW 6 — UNKNOWN TIMEOUT:

Submit Sale
→ Request times out
→ Mark UNKNOWN_OUTCOME
→ Query last online transaction
→ Match fiscal number
→ Mark accepted
→ Do not resubmit
→ Receipt QR is restored

WORKFLOW 7 — CONFIGURATION UPDATE:

Submit Sale
→ MRA requests latest configuration
→ Pause terminal queue
→ Fetch configuration
→ Save new versions
→ Validate mappings
→ Resume queue

WORKFLOW 8 — TERMINAL BLOCK:

Sale response requests block
→ Fetch block message
→ Mark terminal blocked
→ Stop fiscal Sales
→ Notify users
→ Poll unblock status safely
→ Refresh configuration after unblock
→ Resume

WORKFLOW 9 — CERTIFIED OFFLINE SALE:

MRA unavailable
→ Confirm offline eligibility
→ Check thresholds
→ Generate fiscal number
→ Create offline signature
→ Generate offline QR
→ Queue transaction
→ Print receipt
→ Reconnect
→ Upload transaction
→ Reconcile last offline transaction
→ Mark accepted

WORKFLOW 10 — VAT5 RELIEF:

Create relief Sale
→ Enter project and Certificate
→ Validate VAT5
→ Confirm available quantity
→ Exclude VAT correctly
→ Submit EIS Sale
→ Store validation evidence
→ Prevent overuse

WORKFLOW 11 — TENANT DISABLE:

Tenant requests disable
→ System shows pending queue
→ User selects disable-after-clear
→ Queue completes
→ New EIS submissions stop
→ Historical records remain
→ Audit Event is created
