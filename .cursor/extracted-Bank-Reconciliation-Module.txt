InsightBooks V2
Bank Reconciliation Module
Developer & Product Specification
1. Purpose
The Bank Reconciliation Module ensures that the cash balance recorded in InsightBooks matches the balance reported by the business’s bank.
The objective is to:
Detect missing transactions.
Identify duplicate transactions.
Detect bank charges not yet recorded.
Identify direct deposits and direct debits.
Ensure accurate cash balances.
Produce reliable financial statements.
Increase confidence for auditors, banks, and investors.
The module should provide a simple, guided experience while maintaining professional accounting standards.
2. Design Philosophy
Bank reconciliation should not feel like an accounting exercise.
The interface should answer one question:
“Does my accounting system match my bank account?”
The reconciliation screen should be visual, interactive, and easy to understand.
3. Navigation
Financial Management
├── Banking
│ ├── Bank Accounts
│ ├── Bank Transactions
│ ├── Bank Reconciliation
│ ├── Reconciliation History
│ └── Import Statements
4. Bank Account Setup
Allow multiple bank accounts.
Each account should include:
Bank Name
Branch
Account Name
Account Number
Currency
Opening Balance
Opening Date
Status (Active/Inactive)
Support multiple accounts per business.
Example:
National Bank Current Account
Standard Bank Business Account
FDH Operating Account
Ecobank USD Account
5. Import Bank Statements
Allow importing statements using:
CSV
Excel
OFX (future enhancement)
Direct Bank API (future enhancement)
Each imported statement should contain:
Transaction Date
Description
Reference
Debit
Credit
Balance
The system should validate imported data before processing.
6. Automatic Matching Engine
After importing a statement, the system should automatically compare bank transactions with transactions already recorded in InsightBooks.
Matching criteria may include:
Date (within a configurable tolerance)
Amount
Transaction reference
Payee/Payer
Transaction type
Each transaction should receive a confidence score.
Examples:
Exact Match – 100%
Likely Match – 85%
Possible Match – 60%
No Match – 0%
High-confidence matches can be suggested automatically, while lower-confidence matches require user review.
7. Reconciliation Workspace
The workspace should display two synchronized panels.
Left Panel – Bank Statement
Imported bank transactions.
Right Panel – InsightBooks Records
Cashbook and bank-related transactions recorded in the system.
Users should be able to:
Match transactions
Merge multiple transactions when appropriate
Split transactions if needed
Create missing transactions directly from the reconciliation screen
Ignore invalid statement lines with proper justification
8. Reconciliation Summary
Display key reconciliation metrics:
Bank Statement Closing Balance
Book Cash Balance
Difference
Matched Transactions
Unmatched Bank Transactions
Unmatched Book Transactions
Reconciliation Progress (%)
The goal is to clearly show whether the account is fully reconciled.
9. Common Reconciliation Adjustments
The system should assist users in recording common items discovered during reconciliation, including:
Bank charges
Interest earned
Direct deposits
Direct debits
Standing orders
Loan repayments
Returned cheques
Mobile money settlements
Currency exchange adjustments
Each adjustment should automatically create the required accounting entries.
10. Exception Management
Highlight transactions requiring attention.
Examples:
Duplicate payments
Missing receipts
Missing deposits
Unknown transactions
Incorrect transaction amounts
Date discrepancies
Each exception should include suggested actions.
11. Reconciliation History
Maintain a history of every completed reconciliation.
Each record should include:
Bank account
Period
Closing balance
Date completed
User who completed the reconciliation
Approval status
Completed reconciliations should remain available for review and audit.
12. Reports
The module should generate the following reports:
Bank Reconciliation Report
Shows:
Bank statement balance
Book balance
Outstanding deposits
Outstanding payments
Adjustments
Final reconciled balance
Outstanding Transactions Report
Lists all unmatched transactions awaiting resolution.
Bank Charges Report
Summarizes all bank charges recognized during the selected period.
Cash Movement Report
Summarizes cash inflows and outflows by bank account.
Reconciliation History Report
Shows reconciliation activity over time, including completion dates and users responsible.
13. Integration with Accounting
The reconciliation module must integrate directly with:
General Ledger
Cashbook
Accounts Receivable
Accounts Payable
Loan Management
Cash Flow
Financial Statements
Reconciliation adjustments must update the General Ledger automatically.
14. Security
Only authorized finance personnel should be able to:
Import statements
Match transactions
Create adjustments
Complete reconciliations
Reverse reconciliations
Every action must be recorded in the audit trail.
15. User Experience
The interface should feel modern and intuitive.
Include:
Side-by-side transaction comparison
Search and filtering
Match confidence indicators
Progress bar showing reconciliation completion
One-click matching suggestions
Drill-down into source transactions
Responsive design
Keyboard shortcuts for high-volume reconciliations
The user should always know:
What has been reconciled
What remains outstanding
Why differences exist
What action is required to complete the reconciliation
Expected Outcome
The completed Bank Reconciliation Module should enable businesses to reconcile their bank accounts quickly and accurately, maintain reliable cash balances, and produce financial statements that can be trusted by management, auditors, tax authorities, and financial institutions.
The module should minimize manual work through intelligent matching while preserving full auditability and accounting integrity.
