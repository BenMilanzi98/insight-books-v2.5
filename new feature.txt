# 2. 🏗️ Core System Architecture

You are NOT building from scratch.
You are extending:

👉 **Invoices**
👉 **Items (Products/Services)**
👉 **Customers**

---

## 🧱 New Core Entities

### 1. Assets Table

```sql
assets
- id
- name
- category (room, equipment, vehicle, etc.)
- type (rental | hiring)
- branch_id
- status (available, booked, maintenance)
- quantity (for hiring assets)
- created_at
```

---

### 2. Rental_Transactions Table

```sql
rental_transactions
- id
- invoice_id (FK)
- customer_id
- type (rental | hiring)
- start_datetime
- end_datetime
- status (booked, active, completed, cancelled)
- total_amount
- created_at
```

---

### 3. Rental_Items Table

```sql
rental_items
- id
- rental_transaction_id
- asset_id
- quantity
- rate
- total
```

---

### 4. Asset_Availability Table (IMPORTANT)

```sql
asset_availability
- id
- asset_id
- start_datetime
- end_datetime
- status (booked)
- reference_id (rental_transaction_id)
```

👉 This is what prevents double booking.

---

# 3. 🧠 AI Agent System Behavior

Your AI agent (or backend logic) must enforce:

---

## Rule 1: Availability Check

Before confirming:

```
SELECT * FROM asset_availability
WHERE asset_id = ?
AND (
    (start <= requested_end)
    AND (end >= requested_start)
)
```

👉 If exists → BLOCK booking
👉 If none → ALLOW

---

## Rule 2: Status Automation

| Event           | Action            |
| --------------- | ----------------- |
| Booking created | asset → BOOKED    |
| Rental active   | asset → IN USE    |
| Completed       | asset → AVAILABLE |

---

## Rule 3: Invoice Sync

Every rental/hiring MUST:

👉 Generate or link to Invoice

```

```

### Step 5:

System:

# 7. 📊 Availability Engine

---

## Rental (Single Asset)

```
Room 1 → 1 unit only
Status = Booked / Available
```

---

## Hiring (Multiple Units)

```
Generator → 10 units total

Booked = 4  
Available = 6
```

---

## Query Logic

```sql
available = total_quantity - SUM(booked_quantity)
```

# 11. 🔐 Edge Cases (IMPORTANT)

---

### ❌ Double Booking

Handled via availability table

---

### ❌ Partial Returns (Hiring)

Allow:

```
Return 2 out of 5 items
```

---

### ❌ Overbooking Quantity

Block if:

```
requested > available
```

---

### ❌ Cancel Booking

* Remove availability record
* Free asset
